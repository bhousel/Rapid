# Lessons: Build and bundling

`scripts/build_js.ts` and Bun's bundler.

- **`Bun.build` defaults to `format: 'esm'` — which leaks globals for our classic-`<script>` bundles.** Our `main_*.js` entry points have zero `export`s; they only side-effect-attach `globalThis.Rapid`/`d3`/`PIXI`. In ESM format Bun emits those as unwrapped top-level declarations with no closure. Loaded via a classic `<script>` (which is how `dist/index.html` and host apps load `rapid.js`), every top-level `function`/`var` name becomes a property on `window` — so d3-selection's module-scoped `function dispatchEvent(node, type, params)` **clobbered the native `window.dispatchEvent`** (and any other top-level name collision would too). Fix: explicit `format: 'iife'` on every browser bundle in `scripts/build_js.ts`, which wraps everything in `(() => { … })()` while the `globalThis.*` attaches still run inside. This was a **regression from the esbuild→Bun switch**: the old `facebook/Rapid` esbuild build set no `format` and esbuild defaults to `iife` for the browser platform, so it never leaked. Verify empirically — same entry through both bundlers: esbuild → `(() => {…})()`, Bun → flat top-level decls.
- **Leaking is a *classic-script* phenomenon, not an IIFE question.** Module scripts keep top-level declarations in module scope and never touch the global object — true for `<script type="module">` AND module workers (`new Worker(url, { type: 'module' })`). So `rapid-worker.js` was never affected: `WorkerSystem` spawns it as a module worker, so its bundled top-level names can't reach the worker's `self`. We still set `format: 'iife'` on the worker builds as **defense-in-depth** (guards the one future footgun: switching to a classic worker would start leaking into `self` and could clobber native worker methods). Safe because an iife bundle has no top-level `import`/`export`, so it still loads as a module worker *and* stays importable via the cross-origin `import "…/rapid-worker.js"` blob shim in `WorkerSystem._resolveWorkerURL`.
- **Symptom only surfaces when a host reads the clobbered global.** The leak happens on every load but is invisible unless the embedding app (or a co-loaded script) actually uses the clobbered name. It showed up because an app co-loads legacy Rapid2 (esbuild/iife, safe) *and* this Bun-built Rapid3, and something called `window.dispatchEvent`.
