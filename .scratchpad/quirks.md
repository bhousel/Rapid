# Known Quirks

Runtime issues, workarounds, and things that will bite you if you don't know about them.

- **Asset loading vs. render loop timing** — `loadStyleAssetsAsync()` / `loadSchemaAssetsAsync()` at runtime: Pixi keeps rendering during async loading. Current hack: `gfx.pause()` / `gfx.resume()` / `gfx.scene.reset()`. Needs a proper solution.
- **FilterSystem.getMatches** — Skips vertices entirely (returns empty Set). Skips relations unless `tags.type === 'boundary'`. Multipolygon relations get `'area'` geometry, not `'relation'`.
- **RapidSystem._datasetsChanged** — Color-assignment logic is acknowledged as "weird" in code comments. Legacy behavior from before Rapid#1642.
- **ImagerySystem builtins** — `'none'` and `'custom'` sources always exist regardless of merged assets.
- **Structured clone kills DOM objects in workers** — `utilFetchResponse` parses XML into xmldom `Document` objects. These can't survive `postMessage` (structured clone strips prototype methods like `getAttribute`). Services returning XML must either: (a) use `mainThread: true` on `network.fetch`, or (b) parse in the worker and return plain `ParserResult`. `NetworkSystem.worker.ts` provides `fetchAndParseOsmXml` and `fetchAndParseOsmJson` listeners that use approach (b) — parsing happens in the worker, returning structured `ParserResult`.
- **osm-auth mock store vs globalThis.localStorage** — In environments without `localStorage` (unit tests without happy-dom), osm-auth v3.1.1+ uses an internal Map-based mock store. `authenticated()` returns `true` after preauth. Use `oauth.getAccessToken()` (added in osm-auth v3.2.0) to read the token portably — it handles both the browser localStorage path and the mock store path internally.
- **Canvas renderer limitations** — `renderer=canvas` URL param enables Pixi's experimental canvas renderer (v8.16+). Known issues: no Mesh support (dashed lines drawn via DashLine meshes won't render), pattern fills may not work from atlas-packed textures. Atlas textures (symbols, text, tiles) work via canvas-backed `AtlasSource`. `PixiTextures.createTexture()` uses `renderer.generateTexture()` + `renderer.texture.getPixels()` → the canvas path should work since `getPixels` goes through `CanvasTextureSystem.getPixels()`, but test thoroughly.
- **Microtask avalanche from worker results** — Promise `.then()` chains triggered by worker `onmessage` → `pending.resolve()` run as microtasks. The browser event loop MUST drain the entire microtask queue before the next macrotask (including `requestAnimationFrame`). When multiple tiles resolve in the same frame, the entity construction + graph rebase work (~11ms per tile) cascades without yielding. `resultPriority` on `WorkerSystem.dispatch()` mitigates this by routing resolution through SchedulerSystem's frame-budget-aware drain loop. Without `resultPriority`, any new worker listener that triggers heavy main-thread work will hit the same issue.
